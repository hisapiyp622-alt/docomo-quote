# 店舗ログイン・端末間同期の設定手順

この設定を行うと、次のことができるようになります。

- **店舗ID＋パスワード**でログインし、**他店のデータには一切アクセスできない**状態でデータを分離
- 店舗内は**担当者コード**で担当者を切り替え、担当者ごとに見積もりを保存
- 同じ店舗の端末どうし（iPad ⇄ PC）で、店舗名・担当者・料金マスタ・見積もりを**自動同期**
- 解約時にアカウントを無効化すれば、その店舗だけ利用を停止できる

**設定しない場合も、アプリはその端末の中だけで動作します。** その場合は、マスタ設定にある
**店舗ログイン**（端末内モード）で店舗IDとパスワードを設定できます。1台だけで使うならこちらで足ります。

| | 端末内モード（Firebase未設定） | クラウド（この手順） |
|---|---|---|
| 店舗ログイン | マスタ設定で店舗ID・パスワードを登録 | 店舗アカウントでログイン |
| 担当者コード | 使える | 使える |
| 端末間の同期 | なし | あり |
| 他店とのデータ分離 | なし（その端末だけで完結） | あり |
| 強度 | 端末を操作できる人には解析されうる簡易ロック | Firebaseの認証で保護 |

所要時間は15分程度です。作業はすべて [Firebaseコンソール](https://console.firebase.google.com/) 上で行います。

---

## 1. Firebaseプロジェクトを作成する

1. [Firebaseコンソール](https://console.firebase.google.com/) を開き「プロジェクトを追加」
2. プロジェクト名（例: `keitai-quote`）を入力して作成
   - Google アナリティクスは不要（オフでよい）

**1つのプロジェクトで複数の店舗をまかなえます。** 店舗ごとにアカウントを作れば、データは店舗単位で分離されます（手順6）。

## 2. ウェブアプリを登録して設定値を控える

1. プロジェクトのトップで、ウェブアイコン（`</>`）をクリック
2. アプリのニックネーム（例: `keitai-app`）を入力して登録
   - 「Firebase Hosting も設定」はチェック不要
3. 表示される `firebaseConfig` の値をコピーする

## 3. 設定値をアプリに貼り付ける

`firebase-config.js` を開き、`KEITAI_FIREBASE` の各項目を手順2の値に差し替えます。

```js
var KEITAI_FIREBASE = {
  apiKey: "AIza...",
  authDomain: "keitai-quote.firebaseapp.com",
  projectId: "keitai-quote",
  storageBucket: "keitai-quote.firebasestorage.app",
  messagingSenderId: "000000000000",
  appId: "1:000000000000:web:xxxxxxxxxxxx"
};

// 店舗IDをログイン用のアドレスへ変換するときのドメイン
var KEITAI_STORE_DOMAIN = "keitai-quote.example";
```

`projectId` が入力された時点で、ログイン画面とクラウド保存が有効になります。
なおこれらの値は、ウェブアプリでは公開される前提のものです。データの保護は手順5のセキュリティルールで行います。

> **`KEITAI_STORE_DOMAIN` について**
> Firebaseの認証はメールアドレス形式を必要とするため、店舗ID `hannan01` を内部で `hannan01@keitai-quote.example` に変換してログインします。実在するドメインである必要はありませんが、**手順6でアカウントを作るときのアドレスと必ず揃えてください。**

## 4. ログイン方法を有効にする

1. 左メニュー「構築 → Authentication」→「始める」
2. 「Sign-in method」タブ →「メール/パスワード」を選び、**有効にする**（「メールリンク」は不要）

## 5. データベースを作成し、セキュリティルールを設定する

1. 左メニュー「構築 → Firestore Database」→「データベースの作成」
2. モードは**本番環境モード**、ロケーションは `asia-northeast1`（東京）を選択
3. 作成後「ルール」タブを開き、内容を同じフォルダの **`firestore.rules`** の中身に置き換えて「公開」

このルールにより、`stores/{店舗のUID}` 配下へは**その店舗のアカウントでログインしている場合のみ**アクセスできます。他店のデータは読むことも書くこともできません。

## 6. 店舗アカウントを作る（1店舗につき1つ）

1. 「Authentication → Users」→「ユーザーを追加」
2. メールアドレスは **`店舗ID@（手順3のKEITAI_STORE_DOMAIN）`** の形式で入力
   - 例: 店舗IDを `hannan01` にしたい場合 → `hannan01@keitai-quote.example`
3. パスワードを設定し、**店舗IDとパスワード**をその店舗へ伝える
   - 店舗の人が入力するのは `hannan01` の部分だけです（`@` 以降はアプリが補います）

## 7. 担当者と担当者コードを登録する

アプリにログインしたあと、マスタ設定の**店舗設定**で行います（ヘッダーの「担当切替」→「マスタ設定を開く」）。

1. 店舗名と**電話番号**を入力（見積書の下端に自動で入ります）
2. 担当者の名前と**コード**（数字4桁などを推奨）を登録し、必要な人数分「＋ 担当者を追加」
3. コードを設定すると、次回からアプリを開いたときに担当者コードの入力を求められます

担当者・コードの設定は店舗内の全端末に自動同期されます。

## 8. 動作確認

1. アプリを開く → 店舗ログイン画面が表示される
2. 手順6の店舗IDとパスワードでログイン
3. 担当者コードを入力 → その担当者の見積もり画面が開く
4. 別の端末（またはブラウザのシークレットウィンドウ）で同じ店舗・同じ担当者コードでログインし、見積もりが同期されることを確認
5. 画面右上に「同期✓」と表示されれば正常です

ヘッダーの「担当切替」でいつでも担当者コードの入力に戻れます。「ログアウト」で店舗のログインも解除されます。

## 運用のポイント

| やりたいこと | 操作 |
|---|---|
| 店舗を追加する | Authentication → Users でアカウントを1つ追加 |
| 解約・利用停止 | 該当ユーザーを「無効にする」または削除 |
| パスワードを変更する | Users の該当行のメニューから「パスワードを再設定」 |
| マスタ設定のパスワードを決める・変える | マスタ設定 →「マスタ設定のパスワード」 |
| 担当者を追加・削除する | 「担当切替」→「マスタ設定を開く」→ 店舗設定（店舗ID・パスワードが必要） |
| 担当者コードを変更する | 同上。変更は全端末に同期されます |
| データを確認する | Firestore Database → `stores/{UID}`（見積もりは `quotes/{担当ID}`、保存した見積もりは `saved/{担当ID}`、テンプレートは `templates/{担当ID}`、料金マスタの履歴は `history/{ID}`） |
| 料金改定の前に戻す | マスタ設定 →「料金マスタの履歴」→「この内容に戻す」 |

## データの扱い

- クラウドに保存されるのは、店舗名・**店舗の電話番号**・担当者名・担当者コード・料金マスタ・**料金マスタの履歴**・見積もりの入力内容・**保存した見積もりの一覧（名前を含む）**・**テンプレート**です
- **お客様名は端末内にのみ保存され、クラウドへは送信されません**
- ただし、備考欄や引き継ぎシートの「その他」、**保存した見積もりに付けた名前**など、**自由記入欄の内容は同期されます。** お客様の個人情報はこれらの欄に書かないでください
- 通信できない環境でもアプリは動作し、オンラインに戻った時点で同期されます
- 同時に編集した場合は**最後に保存したほうが残ります**（後勝ち）

## 端末内モードの店舗ログインについて

Firebaseを設定しない場合は、マスタ設定 →「店舗ログイン」で店舗IDとパスワードを設定します。

- パスワードはそのままではなく、店舗ごとの値を混ぜたハッシュにして端末内に保存します
- ただし**端末を操作できる人には解析されうる**ため、店頭端末の簡易ロックとお考えください。ブラウザの開発者ツールを使えば、ログインしなくても保存された見積もりを読むことは可能です
- お客様の個人情報を扱う端末では、端末自体のパスコードロックとあわせてご利用ください
- Firebaseを設定すると、この欄は使わず店舗アカウントでのログインに切り替わります

## 自動ログアウト

店舗ログイン（クラウド・端末内モードのどちらでも）を使っている場合、**操作が1時間途切れると自動でログイン画面へ戻ります**。
店頭の共有端末を開いたまま離席したときの備えです。復帰時にはログインからやり直しになりますが、入力中の見積もりは保存されているため失われません。

## マスタ設定を開ける人

料金マスタ・担当者の登録・店舗ログインの設定は、すべてマスタ設定にあります。
**マスタ設定は担当者コードの画面から開きます**（ヘッダーの「担当切替」→「マスタ設定を開く」）。見積もり画面のタブには出ません。
担当者コードを1つも設定していない場合は、「担当切替」を押すとそのままマスタ設定が開きます。
**店舗ログイン（クラウド・端末内モードのどちらでも）を使っている場合、このタブを開くときに店舗IDとパスワードをもう一度求めます。**

- 店舗IDとパスワードを知っている管理者だけがマスタ設定を開けます。担当者コードだけを渡された担当者は開けません
- マスタ設定の中の「**マスタ設定のパスワード**」で、**マスタ設定専用のパスワード**を決められます。決めると、マスタ設定を開くときはそのパスワードだけを聞きます（店舗IDは不要）。店舗のログインパスワードを知らせずに、料金の更新だけを任せたいときに使ってください
- このパスワードは店舗内の全端末で共通です（クラウド利用時は自動で揃います）
- ログアウトしたとき、担当者を切り替えたときに、再びパスワードが必要になります
- 店舗ログインをまだ設定していない場合（クラウド未設定かつ端末内ロック未設定）は、照合するものがないため、そのまま開けます。店舗ログインの設定自体がこのタブにあるためです
- これは**画面上の仕切り**です。料金マスタは端末内に保存されているため、ブラウザの開発者ツールを使える方には読み書きできます。店頭運用での取り違え防止とお考えください

## 担当者コードについて

担当者コードは、**同じ店舗の中で担当者を切り替えるためのもの**です。店舗のログイン（店舗ID＋パスワード）を通過した人だけが使える前提の、簡易的な仕切りとお考えください。

- 端末を共有する場合は、離席時に「担当切替」または「ログアウト」を押す運用をおすすめします（1時間操作がなければ自動でログアウトします）
- **担当者コード（またはお名前のボタン）で入ると、見積もりは3パターンとも初期状態に戻ります。** 次のお客様の入力に前のお客様の内容が混ざらないようにするためです。見積書に出す店舗名・担当者名だけは引き継ぎます
- 作りかけの内容を残しておきたいときは、担当を切り替える前に「保存」タブで保存してください
- コードは店舗の管理者が設定・変更できます
- コードを1つも設定しない場合は、コードの入力を省略して直近に使っていた担当者で開きます
- 一部の担当者にだけコードを設定した場合、コードを設定していない担当者は、コード入力画面に出る名前のボタンから入れます

## 同じ端末で別の店舗にログインする場合

見積もり・料金マスタ・担当者・履歴は、クラウドだけでなく**端末の中にも保存**しています。
そのため、**別の店舗のIDでログインすると、その端末に残っていた前の店舗の内容を自動で片付けます。**
片付けたあと、ログインした店舗の内容をクラウドから読み込みます。

- クラウドには残っているため、**データが失われることはありません**
- ただし、その端末で使っていた店舗に戻るときは、もう一度クラウドから読み直しになります
- **その端末で初めてログインする場合だけ**は、端末内の内容をその店舗の初期値として引き継ぎます
  （新しい店舗を、既存の店舗の設定をひな形にして立ち上げるための動きです）

> **新しい店舗を作るときの注意**
> 既存店舗の端末で新しい店舗IDにログインすると、その店舗のクラウドがまだ空の場合に限り、
> **その端末の内容（店舗名・担当者・料金マスタ）が新しい店舗の初期値として登録されます。**
> 意図しない場合は、新しい店舗の端末で最初のログインを行ってください。

## パスワードが分からなくなったとき

| 分からなくなったもの | 直し方 |
|---|---|
| **マスタ設定のパスワード** | パスワードを聞かれる画面の「**マスタ設定のパスワードを忘れた場合**」を押すと、**店舗ID＋店舗のパスワード**で開けます。開いたら「マスタ設定のパスワード」で決め直してください |
| **店舗のパスワード**（クラウド） | [Firebaseコンソール](https://console.firebase.google.com/) → Authentication → Users → 該当行のメニュー →「**パスワードを再設定**」。<br>**ユーザーを削除して作り直さないでください。** UIDが変わり、`stores/{UID}` にある料金マスタ・見積もりに届かなくなります |
| **店舗ID**（クラウド） | Authentication → Users に一覧があります。`@` より前が店舗IDです |
| **店舗のパスワード**（端末内モード・Firebase未設定） | 照合用のハッシュしか持っていないため、元に戻す方法はありません。そのブラウザのサイトデータ（`Application → Storage → Clear site data`、iPadは設定 → Safari → 履歴とWebサイトデータを消去）を消すとログインが外れます。**その端末の見積もり・料金マスタも一緒に消えます** |

いちばん確実なのは、**店舗IDとパスワードを店舗の管理者が控えておくこと**です。マスタ設定のパスワードは、そこから復旧できます。

## 提供元の表示

`firebase-config.js` の `KEITAI_VENDOR` に提供元名・連絡先・受付時間を入れると、
アプリ内の「情報」に表示されます。**空のままだと「（未設定）」と出ます。**

```js
var KEITAI_VENDOR = {
  name: "〇〇株式会社",
  contact: "support@example.com",
  hours: "平日 10:00〜18:00"
};
```

## 費用の目安

店舗数が数十規模であれば、Firebaseの無料枠（Spark プラン）に収まる想定です。
利用が増えた場合は従量課金（Blaze プラン）へ切り替えてください。
