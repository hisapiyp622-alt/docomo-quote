- [x] **別紙①: 初期費用の配分** … **折半（標準66,000円なら各33,000円）**。導入時の初期設定・研修は
      2名（小川さん＋安藤さん）で店舗訪問する想定＝2人分の稼働の対価。乙が利益を上乗せ・増減して
      販売した場合でも、**甲（安藤さん）の受領額は1店舗あたり最低30,000円**（2026-08-13 確定）

- [ ] 別紙②: サポート分担表（`keitai-app/SUPPORT.md` の内容を甲乙間の分担として写す。一次＝Curacon、二次＝開発元）

- [ ] **締結**（締結日と甲住所は、公開リポジトリのためファイルには書かず**締結時の紙に直接記入**）

### 1-B. 商品の器をCuracon名義に移す（販売開始前が期限）

いまアプリは安藤さん個人のGitHub・Firebaseの上にあります。商品として売るなら
Curaconが握れる形にしておくべきで、**URLの変更は各店舗の端末のデータが切れるため、
1店舗目を売ったあとにはできません。** 販売開始前の今だけ動かせます。

- [ ] **独自ドメイン名を決めて取得する**（Curacon名義推奨。例: mitsumorin.jp など。決まれば設定作業は安藤さん側でやります）
- [ ] **CuraconのGoogleアカウント**（Firebase管理用）を用意して安藤さんに伝える → Firebaseプロジェクト `keitai-quote` のオーナーに追加します
- [ ] **CuraconのGitHubアカウント名**を安藤さんに伝える → リポジトリの権限を付与します（Organization化もこのタイミングで判断）
- [ ] レンタルサーバーへの移管は**できません**（Firebaseは移せない構成のため）。「独自ドメイン＋管理権限の共有」が正解です

### 1-C. Firebaseの有料プラン（Blaze）への切り替えを決める

店舗のデータを預かる以上、**1店舗目を売る前に日次バックアップが必要**です
（規約で「解約後30日データ保持」を約束しているため）。それにはBlaze（従量課金）への切り替えが要ります。

- [ ] 切り替えの承認 … **費用は7店舗規模で月100〜300円程度**の見込み。予算アラートを併設します
- [ ] 支払いに使うカード（Curaconのカードにするか）を決める
- [ ] 決まったら設定作業（日次バックアップ・PITR・予算アラート）は安藤さん側でやります

## 4. 受注したら（1店舗ごとの流れ）

1. **無料お試し（1週間）** … 課金なし。お試し用の店舗ID発行を安藤さんへ依頼
2. **申込書の受領** … Curacon記入欄（受付日・審査・店舗ID・利用開始日）を埋める。反社チェックもここで
3. **店舗IDの発行＝契約成立** … 発行作業は当面安藤さん（Firebaseの操作。手順は `_internal/OPERATIONS.md`）。店舗IDの付け方は「地名＋連番」（例: hannan01）で統一
4. **導入研修** … 契約上の分担は**Curacon**（導入研修・店頭支援・一次サポート＝乙）。`_internal/SETUP.md` の手順どおりに、担当者登録・マスタ設定・最初の見積もりまで一緒にやる
5. **月1回のバックアップ案内** … 「マスタ設定 → バックアップを保存」を月初に取ってもらう。導入時の説明に必ず入れる
6. **初回請求** … 初期費用66,000円＋当月分から
