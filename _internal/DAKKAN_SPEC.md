## 1. 何を作るのか

**店頭で「いまお使いの他社のネット回線から、ドコモ光・home 5G に乗り換えたらどうなるか」を、その場で数字にして見せる道具。**

いま店頭では、お客様の請求書を見ながら口頭と電卓で説明しています。数字が残らないので、お客様は持ち帰って検討できません。ケータイ見積もりが「ドコモにしたらいくらか」を1枚にしたのと同じことを、**「いまのネット回線と比べてどうか」**についてやります。

### 使う場面

| # | いまの回線 | ドコモ側の受け皿 | 申込区分 |
|---|---|---|---|
| A | 他社の光コラボ（SoftBank 光・楽天ひかり・ビッグローブ光 など） | ドコモ光 | **事業者変更**（工事不要） |
| B | フレッツ光（NTT東西と直接契約） | ドコモ光 | **転用**（工事不要） |
| C | 独自回線（eo光・auひかり・NURO 光・コミュファ光 など） | ドコモ光 | **新規**（工事あり） |
| D | CATV（J:COM NET など） | ドコモ光 | **新規**（工事あり） |
| E | 他社ホームルーター（SoftBank Air・WiMAX・Rakuten Turbo など） | **home 5G（既定）**。光を望まれたらドコモ光（新規） | home 5G は工事不要 |

阪南店の商圏は関西です。**関西で実際に多いのは eo光・J:COM** なので、優先順位は安藤さんに確認してください（第5章）。

### 完成の判定

**「お客様が持ち帰って家族に説明できる1枚」が出ること。** 口頭の補助ではなく、紙として成立していることが条件です。

## 2. どこに作るか

### 結論：`dakkan-app/` として単体で作る。ただし**最初から統合を前提にした書き方**にする

イエナカは単体アプリとして作ったあとでケータイ製品版へ統合しました。そのとき **画面idと `data-` 属性をひとつ残らず `ie` 接頭辞へ付け替える作業**が発生しています（`_internal/IENAKA_MERGE.md` の「統合で実際に起きたこと」参照）。同じことを繰り返さないために、**最初から次を守ってください。**

1. **画面のidは全部 `dk` 接頭辞にする**
   `carrier` ではなく `dkCarrier`、`monthly` ではなく `dkMonthly`
2. **`data-` 属性も `dk` 接頭辞にする**
   `data-opt` ではなく `data-dkopt`
3. **計算と画面描画を、保存・同期・ログインから切り離しておく**
   イエナカでは `calc()` が `state` と `save()` に直結していたため、切り出すのに手間が掛かりました。
   最初から次の形にしておいてください。

```js
window.KQ_DAKKAN = {
  defaultState: defaultState,   // 入れ物の初期値
  attach: function (state, onChange) {},  // 外から状態を渡す
  bind: bind,                   // イベント登録（1回だけ）
  syncForm: syncForm,           // 状態 → 画面
  calc: calc,                   // 計算（画面に触らない）
  render: render,               // 画面の表示だけ
  sheetHtml: sheetHtml          // 別紙の中身（表題・発行元は呼び出し側が付ける）
};
```

`keitai-app/ienaka.js` が**まさにこの形**なので、そのまま手本にしてください。

### ファイル構成（`dakkan-app/`）

```
dakkan-app/
  index.html
  app.js            ← 単体で動かすための入れ物（ログイン・保存・担当者・マスタ設定）
  dakkan.js         ← ①いまのご契約・④比較・別紙。window.KQ_DAKKAN を公開する
  ienaka.js         ← keitai-app/ienaka.js のコピー（「ドコモにした場合」の入力と計算）
  data.js           ← 他社回線の料金・違約金・手数料（マスタ設定で編集できる）
  style.css
  sw.js
  manifest.webmanifest
  icon.svg
  firebase-config.js
```

- **`app.js` の手本は `ienaka-app/app.js`**（単体製品版の入れ物＝ログイン・保存・担当者・マスタ設定を既に実装済み）。localStorage のキーは `dk-` 接頭辞にして、`kq-` / `dq-` / 単体イエナカのキーと衝突させないこと（同一ドメインに同居するため。`HANDOVER.md` 参照）
- **`firebase-config.js` は `ienaka-app` と同じく空設定で出荷**（店舗側で設定する方式）。`keitai-app` の `keitai-quote` プロジェクトへ相乗りするかは**統合時の判断**であり、単体版で勝手に共有しない
- **「ドコモにした場合」は `keitai-app/ienaka.js` をコピーして同梱し、`KQ_IENAKA` として使う。** dakkan-app の画面に「ドコモ光・home 5G の入力」ブロック（イエナカの①〜⑤）を置き、`app.js` が `KQ_IENAKA.attach()` と `KQ_DAKKAN.attach()` の両方に状態を渡す。**コピーの正は keitai-app 側。** 直したいことが出たら keitai-app 側を直してからコピーし直す（`CLAUDE.md` の「修正の反映先」と同じ考え方）
- `app.js` と `dakkan.js` を分けるのが肝です。**統合するときは `dakkan.js` と `data.js` だけを移せば済みます**（`KQ_IENAKA` はケータイ製品版に既にあるため、同梱コピーは捨てる）

## 3. 画面と機能

### ① いまのご契約（他社側）

お客様の請求書を見ながら入力します。**入力の手数を減らすことが最優先**です。店頭は時間がありません。

| 項目 | 形 | 備考 |
|---|---|---|
| 回線の種類 | 選択 | 光コラボ／フレッツ光／独自回線／CATV／ホームルーター。**申込区分（第1章の表）を自動で決める**ために使う |
| 事業者名 | 選択＋自由入力 | data.js の一覧から。無ければ手入力 |
| 月々のお支払い | 入力 | **請求額をそのまま入れる。** 内訳は聞かない |
| うちオプション分 | 入力（任意） | ルーターレンタル・セキュリティ等。**④の比較には使わない。** 別紙に「うちオプション ◯円/月 は乗り換え後に不要になる見込み」と注記で出すだけ |
| スマホとのセット割 | チェック＋金額 | おうち割 光セット・auスマートバリュー など。**乗り換えると他社スマホ側が上がる**（④の注意） |
| 更新月かどうか | 選択（更新月／それ以外／不明） | 違約金の有無に関わる |
| 解約違約金 | 入力 | 分からなければ空欄のまま出す（「要確認」と表示） |
| 工事費の残債 | 入力 | 解約時に一括請求されることが多い |
| 撤去工事費 | 入力 | **独自回線のみ表示**（auひかり戸建など、撤去が条件になる場合がある） |

### ② 乗り換えに掛かるもの（出ていく側＋入ってくる側）

**ここが「奪還」の肝です。** お客様が一番気にするのは「違約金と工事費」で、実際には掛からない・実質無料になる場合が多いのに誤解されています。それを数字で見せます。

**出ていく側（他社に払うもの）** … ①で入れた 違約金・工事費残債・撤去工事費 の合計。
事業者変更承諾番号の発行に手数料が掛かる会社もあります（会社ごと。data.js に持たせる）。

**入ってくる側（ドコモに払うもの）** … **`KQ_IENAKA.calc()` の初期費用をそのまま使う。** 自前で計算し直さないこと。

- 事務手数料 4,950円・新規工事料 28,600円（実質無料特典・エントリー不要）は**イエナカ側が既に持っています**
- 事業者変更・転用は工事不要（`applyType` が `jigyosha` / `tenyo` のとき、イエナカ側で工事料 0 になります）
- 回線の種類から自動で提案してください（担当者が変更できる形で）:
  光コラボ→`jigyosha`（事業者変更）／フレッツ光→`tenyo`（転用）／独自回線・CATV→`shinki`（新規）／
  ホームルーター→イエナカ側の商材を `home5g` に提案（home 5G は工事も申込区分もなし。光を望まれたら `shinki`）

### ③ ドコモにした場合

**イエナカの見積もりを使います。二重入力させないこと**（第7章の連携を参照）。

- 月額は `KQ_IENAKA.calc()` から取れます（`segs` の最後が通常時の月額）
- home 5G も同じ入り口です（`product: "home5g"`）

### ④ 比べる

出す数字は3つだけにしてください。多いと伝わりません。

```
いまのお支払い（ネット回線）    6,600円/月
ドコモ光にした場合              4,400円/月    −2,200円/月
乗り換えに掛かる費用            違約金 4,180円＋工事費残債 11,000円＋事務手数料 4,950円
────────────────────────────
◯か月で追いつきます
```

**計算の規定（実装で迷わないための決め）**

- 「◯か月で追いつく」は **(乗り換え費用) ÷ (月々の差額) を切り上げ**（`Math.ceil`）。
  切り捨てると実際より早く追いつくように見えて嘘になります。
  検算例: (4,180＋11,000＋4,950) ÷ 2,200 ＝ 9.15 → **10か月**
- 差額が0以下のときは出さない（追いつかないのに数字を出すと嘘になります）
- **空欄（要確認）の費用項目は合計に入れず、④と別紙に「要確認: 解約違約金」と赤字で出す。**
  0円として合計すると「安く見せた」ことになります
- **要確認が1つでも残っているあいだは「◯か月で追いつく」を出さない**
  （不完全な合計で断定しない。「解約違約金のご確認後に表示します」と出す）
- 更新月「更新月」→違約金0円扱い。「不明」→違約金は要確認扱い

**セット割の注意（二重計上・計上漏れの両方に気をつける）**

- **ドコモ光セット割（ドコモのスマホ側が下がる分）** は、ケータイ見積もりの③割引で計上済みです。**この別紙で足さない**（二重計上になる）。「スマホのセット割はスマホの見積書をご覧ください」と書き添えるだけにする
- **他社のセット割（おうち割など）が外れて他社スマホ側が上がる分**は、①でチェックした場合に**注意書きとして必ず出す**。スマホの比較はこのツールの範囲外なので、金額を断定せず「他社スマホの割引 ◯円/月 が外れます」とだけ出す

### ⑤ 別紙（1枚）

- ケータイ見積もりの「光のみ別紙（3枚目）」と同じ体裁（`keitai-app/app.js` の `ienakaOnlySheet()` が手本）
- 「料金データ基準日」と「他社の公式な案内ではない」旨を必ず入れる（第4章・第6章）
- **A4 1枚に収める**（`pdfinfo` で確認）

## 4. 料金データの扱い（絶対に守る）

このリポジトリの一貫したルールです。

1. **一次情報（各社の公式サイト）で確認できた値だけを入れる。**
2. **確認できなかったものは空欄にして、店舗に登録してもらう。** 推測した数字を入れない。
   （でんき・ガスの連絡先で、確認できなかった5社を空欄にしたのと同じ扱いです）
3. **出典URLと確認日を `data.js` にコメントで残す。**
4. **すべてマスタ設定から編集できるようにする。** 他社の料金は頻繁に変わります。
5. **画面と別紙に「料金データ基準日」を出す。** 古い数字で比較すると、そのままクレームになります。

data.js に持たせるもの（会社ごと）:

- 標準月額（戸建／マンション）… 請求額が未入力のときの参考表示。戸建／マンションの別は**イエナカ側の住居タイプ（`store.ienaka.housing`）を使う**（①で聞き直さない）。請求額の入力があれば常にそちらを優先
- 解約違約金の目安（更新月以外）／更新月なら0 … **第5章Q2で「目安を持つ」と決めた場合だけ**
- 撤去工事費（独自回線で撤去が条件になる会社のみ）
- 事業者変更承諾番号の発行手数料
- 解約・事業者変更の連絡先（でんき・ガスの `energyCompanies` と同じ形式。電話番号も一次情報で確認できた分だけ）

確認しに行く先（2026-07 時点の想定。実際のURLは各社サイトで辿ること）:

- NTT東日本・西日本 … フレッツ光の解約・転用承諾番号のページ
- SoftBank 光・楽天ひかり・ビッグローブ光 など光コラボ各社 … 解約金・事業者変更のページ
- eo光・auひかり・NURO 光・コミュファ光・J:COM … 解約金・撤去費用のページ（**関西は eo光・J:COM を優先**）
- SoftBank Air・WiMAX（UQ/各社）・Rakuten Turbo … 解約時の残債のページ
- ドコモ … 事業者変更（入）・転用の条件、工事費実質無料の条件（`keitai-app/ienaka.js` に出典コメントあり）

**自動取得（スクレイピング）はアプリに入れないでください。** 各社の規約と安定性の問題があります。値は人が確認して data.js を更新する運用にします（ドコモのRSS監視と同じ考え方。`_internal/RSS_WATCH.md` 参照）。

## 6. 注意（販売する以上、ここは外せない）

### 範囲を広げるときの覚え書き（スマホの奪還・解約新規）

**スマホ（携帯回線）の他社比較は、2026-07-30 にイエナカ限定へ絞ったため範囲外です。**
将来スマホへ広げる場合は、MNP転出・端末残債・みんなドコモ割・キャリアメール持ち運びなど、ネット回線とは別の項目一式が要ります。その時は改めて指示書を書き直してください。

**解約新規の案内は 2026-07-29 に保留となりました。いまは作りません。**

再開の判断材料として、保留の背景を残しておきます。

**解約新規は、代理店とドコモの取り決めによっては制限されていることがあります。**
ツールが「解約新規を勧める道具」に見えると、**代理店が導入できないどころか、売る側のリスクになります。**
製品版と抱き合わせで販売する前提なので、ここは慎重に決める必要があります。

再開する場合に守ること:

- **既定は「継続」。** 解約新規は選んだときだけ出す
- **失うもの**を、**得るものと同じ大きさで、同じ画面・同じ紙に出す**
- 「おすすめ」「有利」といった断定の言葉を使わない。**数字を並べて、判断はお客様と担当者に委ねる**
- 実際に何が失われるかは、その時点のドコモの規約を確認して `data.js` に持たせる（店舗が編集できる形に）

**再開するときは、まず安藤さんに「どこまで踏み込むか」を確認してください。**

### 他社の料金を扱うこと

- 基準日を必ず出す（第4章）
- 「他社の公式な案内ではない」旨を、ケータイ見積もりの `TERMS.md` 第2条と同じ形で入れる
- 断定の言葉（「絶対お得」「必ず安くなる」）を使わない。数字を並べて判断を委ねる
- **お客様の請求書の内容は個人情報です。** ケータイ見積もりと同じく、**お客様名はクラウドへ送らない**ルールを守ってください（`keitai-app/app.js` の `quotePayload()` が参考になります。郵便番号は 1.21.0 から同期対象なので、扱いを変えるときは安藤さんに確認）

## 7. ケータイ見積もり・イエナカとの連携

### 7-1. いますぐ使える方法（単体アプリのまま繋ぐ）

**`kq-handoff-v1` の仕組みが既にあります。** 同じドメインに置いたアプリ同士が、localStorage 経由で店舗名・担当者名・お客様名を渡し合うものです。

- 書き出す側 … `keitai-app/app.js` の `initIenakaLink()`
- 受け取る側 … 同 `takeHandoffFromIenaka()`
- 中身 … `{ from, storeName, storeTel, staffName, custName, at }`。**10分で期限切れ**にして、読んだら消す

**注意: いまの受け取り側は `from === "ienaka"` しか読みません。** 奪還ツールから渡すには、`from: "dakkan"` を書き出したうえで、keitai 側の受け取り判定に `"dakkan"` を足す小さな改修が要ります。この改修はケータイ製品版のリリースなので、`APP_VERSION`・`CACHE` に加えて **`keitai-app/changelog.js` の先頭に1件足すこと**（足し忘れると店舗側に新着の知らせが出ません。`_internal/OPERATIONS.md` 参照）。

**渡す内容を増やすときは、`custName` 以外にしてください。** 見積もり内容（月額・回線）まで渡すと、handoff が実質的なデータ同期になり、どちらが正なのか分からなくなります。

### 7-2. 最終形（ケータイ製品版のタブとして統合）

イエナカと同じ形にします。**イエナカの実装（`keitai-app/ienaka.js` と `app.js` の組み込み部）がそのまま手本です。**

| 決めること | どうするか | 理由 |
|---|---|---|
| 状態の置き場所 | **`store.dakkan`（パターンA/B/Cの外）** | ネット回線は世帯に1本。「いまのご契約」も世帯に1つ。光を `store.ienaka` に置いたのと同じ理由 |
| 保存・同期 | `store` ごと保存されるので自動で付いてくる | ただし**復元の3経路すべて**に通すこと（下記） |
| タブ | `<section id="tab-dakkan">` を足し、タブに「他社比較」 | |
| 見積書 | `sheetScope` に「他社比較（別紙）」を足す | 光の別紙（`sheet-page3`）と同じく、**別紙の1枚**にする。スマホの見積書に混ぜない |
| 引き継ぎシート | 「ドコモ光・home 5G」の欄に「他社からの乗り換え」行を足す | 後工程が 事業者変更承諾番号・転用承諾番号・解約連絡の要否 を把握できるように |

**復元の3経路**（イエナカで一度漏らして直した箇所です。必ず全部通してください）:

1. `loadState()` … 起動時
2. `loadSavedQuote()` … 保存した見積もりを開いたとき
3. `applyRemoteQuote()` … 端末間同期で受け取ったとき

`keitai-app/app.js` の `applyIenaka()` が、この3つから呼ばれる共通関数です。同じ形で `applyDakkan()` を作ってください。**入れ物（オブジェクト）は差し替えず、中身だけ入れ替える**こと（モジュール側が参照を握っているため）。

### 7-3. イエナカとの連動（ここがこのツールの本体）

**「ドコモにした場合」はイエナカの見積もりそのものです。** 奪還ツール側でドコモ光の料金を持たない・計算しないこと。

- 月額・初期費用は `KQ_IENAKA.calc()` から取る
- 回線の種類から `applyType`（新規／転用／事業者変更）を提案し、`store.ienaka.applyType` へ反映する
- **セット割を二重に数えない。** ドコモ光セット割はケータイ側③で計上済み（第3章④）
- 引き継ぎシートのQR（トスアップフォーム・ルーター申込など）は 1.24.0〜1.28.0 で入れた仕組みがあります。奪還経由の受付でも同じ条件でそのまま出ます

### 7-4. 抱き合わせ販売の観点

安藤さんの目的は**製品版との抱き合わせ販売**です。作りながら次を意識してください。

- **別料金のオプションとして売る場合**、機能を出し分ける器が要ります。
  「契約・課金の器（契約者名・プラン・有効期限・状態を持たせる）」という構想が `_internal/SALES.md` 第6章にありますが、**設計も実装もまだです**（Firestore の `stores/{uid}` 配下に持たせるのが自然、という程度）。
  奪還ツールを統合するときが、この器を作る良いきっかけになります
- **標準機能として付ける場合**、器は不要です。タブを足すだけで済みます
- どちらにするかは価格が決まってからの判断です（利用料金は 2026-07-30 時点で未定）

## 8. 作業の進め方

`CLAUDE.md` の「リリース手順」に従ってください。要点だけ再掲します。

1. `node --check` で構文を確認
2. **Playwright で実際に動かして確認する。** 見た目だけでなく、数字が合っているかを検算する
   ```
   const { chromium } = require('/opt/node22/lib/node_modules/playwright');
   chromium.launch({ executablePath: '/opt/pw-browsers/chromium' })
   ```
   ローカルで動かすときは `python3 -m http.server` を使ってください（`file://` ではダウンロードや fetch が動きません）
3. **紙になるものは `pdfinfo` でページ数を確認する**
   ```
   page.emulateMedia({media:'print'}); page.pdf({format:'A4'});
   ```
   ケータイ見積もりの見積書はA4 2枚、光の別紙は1枚に収めています。**奪還の別紙も1枚に収めてください**
4. `APP_VERSION` と `sw.js` の `CACHE` を必ず両方上げる
5. コミット → rebase → force-with-lease で push → PR（draft → ready → squash マージ）
6. GitHub Pages に出るまで確認してから完了報告

### 検算の例

金額を出す機能は、**手計算と突き合わせてから完了報告してください。**
