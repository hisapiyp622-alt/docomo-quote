Routine（毎朝8時）がこのファイルを読み、確認したら「最終確認」を更新してコミットします。

## 拾う記事の見分け方

RSSに入っているのは**日付・タイトル・URLだけ**で、金額は本文（HTMLまたはPDF）にあります。
まずタイトルで絞り、残ったものだけ本文を読みます。

**拾うキーワード（タイトルに含まれるもの）**

```
料金プラン / 新料金 / 料金改定 / 改定 / 値上げ / 値下げ / 見直し
提供開始 / 提供終了 / 受付終了 / 新設 / 変更
割引 / キャンペーン / 特典 / 還元
爆アゲ / ポイ活 / dカード / dポイント / あんしん / 補償
eximo / irumo / ahamo / ドコモ MAX / ドコモ mini / ギガホ / ギガライト
U15 / U22 / はじめてスマホ / キッズケータイ / データプラス
いつでもカエドキ / 事務手数料 / 頭金
```

**拾わないもの**（見出しで判断できるもの）

- 通信障害・工事・災害の支援措置
- 受賞・調査結果・イベント・スポーツ・提携の発表
- 法人向けソリューション、6G・研究開発のトピックス
- ドコモFG（金融）のうち、料金や割引に関係しないもの

迷ったら**読む**。読んだうえで影響なしと判断したものは、その旨を報告に1行書く。

## 影響があったときの流れ

**自動でマージしません。金額はお客様の見積書に載るため、必ず人が確認します。**

1. Routine が本文を読み、`keitai-app/data.js` への影響を判断する
2. 影響があれば `data.js` を直し、`masterVersion` を +1、`updated` を改定日にする
3. `app.js` の `APP_VERSION` と `sw.js` の `CACHE` を上げ、`changelog.js` に1件足す
4. ブランチ `claude/docomo-estimate-print-layout-tbeyi6` に push し、**Pull Request までで止める**
5. 安藤さんが内容を確認してマージ → GitHub Pages が配信
6. 店舗のアプリに「料金表の更新があります」と出る → 店舗が確認して適用

つまり金額には **Routineの読み取り → 安藤さんの承認 → 店舗の適用** の3段の確認が入ります。

## やらないこと

- **推測で数値を入れない。** 本文で確認できた金額だけを反映する。
  「たぶんこうだろう」は書かず、報告に「要確認」と書いて止める
- **店舗のマスタを直接書き換えない。** 配信の仕組み（`masterVersion`）を通す
- 提供開始が先の話（例: 3か月後から）のときは、**開始日を `changelog.js` と PR に明記**する。
  先の日付の料金をいま配ると、店頭で誤案内になる
