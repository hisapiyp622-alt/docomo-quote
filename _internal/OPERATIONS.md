### 3文書を書くときの注意

- **約束できないことは書かないでください。** 書いた内容がそのまま義務になります（とくに `SUPPORT.md` の応答目安と、料金改定のお知らせ）
- **価格は一度出すと下げられません。** 最初の1店舗に提示する前に決めてください
- 3文書は `keitai-app/` に置いてあり、**アプリの「情報」から誰でも読めます。** 社内向けの注意書きをこの3文書に書かないでください（この運用手順書に書いてください）
- 埋め終えたら、各文書の冒頭にある「本書は制定前の案です」の行を削除してください

## 店舗を追加する

1. [Firebaseコンソール](https://console.firebase.google.com/) → Authentication → Users →「ユーザーを追加」
2. メールアドレス: `店舗ID@keitai-quote.example`（`@` 以降は `keitai-app/firebase-config.js` の `KEITAI_STORE_DOMAIN` と揃える）
3. パスワードを設定（8文字以上・推測しにくいもの）
4. 店舗IDとパスワードを、店舗の管理者へ**口頭または安全な方法で**伝える
5. 店舗側で `SETUP.md` の手順7（担当者の登録）を実施してもらう

**店舗IDの付け方**は最初に決めて統一してください（例: `hannan01` のように 地名＋連番）。

## 利用を停止する（支払い遅延・解約）

1. Authentication → Users → 該当ユーザーの行のメニュー →「**ユーザーを無効にする**」
2. 次にアプリを開いた時点でログインできなくなります

**ユーザーを削除しないでください。** 削除するとUIDが変わり、`stores/{UID}` 配下の料金マスタ・見積もりに二度とアクセスできなくなります。復活させる可能性がある間は「無効にする」を使ってください。

## 解約後のデータ削除

保持期間（`keitai-app/TERMS.md` 9条2項）が過ぎたら、Firestore Database で `stores/{該当UID}` のドキュメントを配下ごと削除します。
そのあとで Authentication のユーザーを削除してください。

## パスワードの再設定

Authentication → Users → 該当行のメニュー →「パスワードを再設定」。
アプリ側の「マスタ設定のパスワード」は、店舗の管理者が店舗ID・パスワードで入って決め直せます（`SETUP.md` 参照）。

## 費用の見込み

Firebase の無料枠（Sparkプラン）は、Firestore が 1日あたり読み取り5万・書き込み2万、保存1GiB です。
**数十店舗までは無料枠に収まる想定**です。超えた場合は Blaze プラン（従量課金）に切り替えます。

コンソールの「使用量」で、店舗数が増えたときの推移を月1回は確認してください。

## バックアップ

**現在、Firestore の自動バックアップは設定していません。** 店舗数が増えたら、Blazeプランに切り替えたうえで
定期エクスポート（Cloud Scheduler + Firestore export）の設定を検討してください。

暫定的には、各店舗のマスタ設定にある「現在のマスタ構成をコピー」で控えを取れます。

## リリースの手順

1. `keitai-app/` を変更する
2. `app.js` の `APP_VERSION` と `sw.js` の `CACHE` を**両方**上げる
3. **`changelog.js` の先頭に1件足す**（`v` は上げた `APP_VERSION` と揃える）
4. main にマージすると GitHub Pages へ自動で反映される
5. 各店舗の端末は、次に開いたときに自動でリロードされる

**バージョンを上げ忘れると、端末に古い版が残り続けます。**
**`changelog.js` に足し忘れると、店舗側に「新着」が出ません。** 書く内容は
仕組みの説明ではなく、店舗の方から見て「何ができるようになったか」にしてください。

## 料金改定を各店舗へ配る

ドコモの料金が変わったときの手順です。**店舗のマスタはこちらの `data.js` より優先される**ため、
`data.js` を直すだけでは既存店舗には届きません。版数を上げて知らせる必要があります。

1. `keitai-app/data.js` の該当する金額を直す（一次情報で確認してから）
2. **`masterVersion` を +1 する**（これを忘れると誰にも届きません）
3. `updated` を改定日にする（見積書の「料金データ基準日」に出ます）
4. `app.js` の `APP_VERSION` と `sw.js` の `CACHE` を上げ、`changelog.js` に1件足す
5. main へマージ → GitHub Pages が配信

店舗側では次のようになります。

- マスタ設定の先頭に「料金表の更新があります」と出る
- 担当者コードの画面にも一行出る（マスタ設定を毎日は開かないため）
- 「変わる内容」で金額の前後を確認してから「この内容に更新する」を押す
- 適用前の内容は履歴に残るので、あとから戻せる

### 更新されるもの・されないもの

| 更新される | 更新されない（店舗のもの） |
|---|---|
| 事務手数料 | 店頭頭金の初期値 |
| プランの基本料金・割引・爆アゲ区分・ポイ活上限など | プラン名 |
| 通話オプションの金額 | 店舗が登録したプラン |
| ドコモ商材の金額・選択肢・爆アゲ率・説明 | オプションの名前・置き場所・並び順 |
| 初期費用の定番項目の金額・支払い先 | 店舗独自（`own: true`）にしている項目すべて |
| キャンペーンの期間・対象・割引額 | アクセサリ（すべて店舗の商品） |
| 初期データに増えた新項目（削除済みのものは除く） | 担当者・店舗名・電話番号・テンプレート・保存した見積もり |

**店舗がドコモ商材の金額を自分で変えていた場合は上書きされます。** 意図的に変えていた店舗は、
「変わる内容」を見て気づけますし、適用後に履歴から戻せます。

### 注意

- **`masterVersion` は必ず整数で +1。** 下げたり飛ばしたりしない
- 店舗が「あとで」と放置しても、次に開いたときにまた出ます（消えません）
- 適用は店舗の操作です。**こちらから強制はできません。** 改定日に確実に反映させたい場合は、
  店舗へ連絡して適用してもらってください

## データのバックアップ

守るべきものは2つあり、それぞれ担当が違います。

### 1. 店舗のデータ（店舗が自分で取る）

アプリの **マスタ設定 → バックアップ** から、店舗情報・担当者・料金マスタ・
マスタ履歴・保存した見積もり・テンプレートを1つのJSONファイルに書き出せます。
「バックアップから復元」で戻せます。

- **お客様名は既定で含まれません。** チェックを入れたときだけ含まれます。
  含めたファイルは個人情報を含むので、保管場所に注意するよう店舗に伝えてください
- 復元すると、戻す前の内容が料金マスタの履歴の先頭に残ります
- **導入時の説明に必ず入れてください。** 「月に一度、月初に取る」くらいの案内が現実的です

これは**誤操作からの復旧**に効きます。クラウド同期は「いまの状態を写す」ものなので、
間違えて消した内容は同期先でも消えます。バックアップはそこを埋めるものです。

### 2. Firestore 全体（販売側が取る）

店舗が全部消してしまった、アカウントを間違えて削除した、といった事故に備えるものです。

**Firestore の自動バックアップには Blaze プラン（従量課金）が必要です。**
`keitai-quote` プロジェクトが Spark（無料）のままなら、まず切り替えが要ります。
店舗数が少ないうちは無料枠に収まる見込みですが、課金の有効化そのものは判断事項です。

設定するときの手順:

1. [Firebaseコンソール](https://console.firebase.google.com/) → `keitai-quote` → 歯車 → 使用量と請求 → Blaze へ変更
2. Firestore Database → バックアップ → **バックアップのスケジュールを作成**
3. 推奨: **日次・保持14日**（店舗数が少ないうちはこれで十分です）
4. あわせて **PITR（ポイントインタイム リカバリ）** を有効にすると、直近7日は任意の時点へ戻せます

**Blaze に切り替えるまでの間の代替**として、店舗側のバックアップ（上記1）を
確実に取ってもらうことで、実務上の最悪は避けられます。
ただし**店舗が取っていなければ何も残りません**ので、恒久策にはなりません。

### いつやるか

`_internal/SALES.md` の段取りでは、**最初の1店舗を売る前**に2を用意する想定です。
他社の店舗データを預かった時点で「消えました」は通らないためです。
