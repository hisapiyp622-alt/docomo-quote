## 方針

**イエナカをケータイ製品版の「タブ」として取り込み、イエナカの入力内容を
ケータイの保存領域（`store.ienaka`）に入れる。**
（パターンA/B/Cの外に置く。理由は「見積もりの単位」を参照）

こうすると次がすべて「ただで」付いてきます。

- ログイン・担当者・店舗情報・電話番号 … ケータイ側のものを共有
- 保存（名前を付けて保存）・テンプレート … `store` ごと保存されるため自動的に対応
- クラウド同期 … `quotes/{staffId}` の中の1フィールドになるので**衝突しない**
- 自動ログアウト・立ち上がりの目隠し・情報画面・更新履歴 … 共通

### やること

1. **`keitai-app/ienaka.js`（新規）**
   `ienaka-app/app.js` から**計算と画面描画だけ**を移植し、別のIIFEにして公開する。

   ```js
   window.KQ_IENAKA = { defaultState, calc, bindEvents, syncForm, sheetRows, IENAKA_OPTS };
   ```

   **保存・同期・ログイン・担当者の機能は移植しない**（ケータイ側が持つ）。
   `ienaka-app/app.js` のうち移植するのは `defaultState` `calc` `renderOpts` `renumberSteps`
   `renderExtras` `syncForm` `applyDefaults` と `IENAKA_OPTS` 周辺。
   `cloudOn` `storeDoc` `quoteDoc` `pushConfig` `pushQuote` `watchStore` `watchQuote`
   `showLogin` `switchStaff` `renderStaffSelect` `renderConfigTab` は**移植しない**。

   **名前の衝突に注意。** `$` `num` `yen` `esc` `calc` `save` `defaultState` `activeStaff` は
   ケータイ側にも同名があります。別IIFEにすれば衝突しませんが、うっかり同じスコープに
   入れないこと。

2. **`keitai-app/index.html`**
   `ienaka-app/index.html` の ①商材 〜 ⑤特典 を `<section id="tab-ienaka">` として追加し、
   タブに「イエナカ」を足す。**id が衝突しないよう、すべて `ie` 接頭辞を付ける**
   （`product` → `ieProduct`、`dcard` → `ieDcard` など。ケータイ側にも `dCard` があるため必須）。

3. **`keitai-app/style.css`**
   `ienaka-app/style.css` は「ルートの `style.css` ＋ `ienaka/ienaka.css`」の連結なので、
   **後半のイエナカ固有部分だけ**を追加する。前半は既にあるものと重複します。

4. **`keitai-app/app.js`**
   - `store` に `ienaka: KQ_IENAKA.defaultState()` を足す（`state` ではなく `store` 直下）
   - タブ切替に `ienaka` を足す
   - 見積書タブに **「スマホのみ／光のみ／両方」の切替**を足す
   - 「両方」のとき、**月額の合計**と**初期費用の合計**を出す。
     セット割はケータイ側で既に引かれているので、**二重に引かないこと**
   - 引き継ぎシートにも光の内容を出すか決める（初手は出さなくてよい）

5. **`ienaka-app/` はそのまま残す**
   統合版が固まるまで単体アプリを消さない。固まったら「イエナカ単体版は
   ケータイ見積もりに統合されました」と案内して畳む。

### 見積書の見せ方（A4 2枚を守る）

いまケータイの見積書はA4ちょうど2枚です。光の内容を足すと**溢れます**。

- 「両方」のときは、光は**要約1〜2行**（商材名＋月額＋初期費用）にとどめる
- 光の明細が要るときは「光のみ」で別紙にする
- **必ず `pdfinfo` でページ数を確認する**

## 見積もりの単位（2026-07-28 決定）

スマホは1人1回線ごと、光は1世帯に1本です。

**光は世帯で共通とします。**（安藤さんの判断）

つまり `state.ienaka` はパターンA/B/Cで**共有**し、パターンを切り替えても光の内容は変わりません。
スマホの案を3つ並べて比べながら、光は1本という見せ方になります。

実装上の注意:

- 光の内容は `state`（パターンごと）ではなく、**パターンの外**に置くこと。
  `store.ienaka` のように `store` 直下へ持たせ、`store.patterns[]` には入れない
- 保存・テンプレート・クラウド同期の対象に含めること（`store` ごと保存すれば自然にそうなる）
- 「現在の内容を次のパターンへコピー」で光をコピーしない（共通なのでコピー不要）
- 見積書で「両方」を選んだとき、光の行は**どのパターンでも同じ**になる
